# Локальный запуск и разработка

## Новая установка

Нужны работающий Docker Engine и Docker Compose. В корне проекта:

```bash
cp .env.example .env
```

Заполните `WORLD_URL`, `DB_PASSWORD`, `ADMIN_USERNAME`, `ADMIN_PASSWORD`
по [README](README.md). Для локального запуска оставьте `WORLD_URL=http://localhost:3002`
и `BIND_ADDRESS=127.0.0.1`.

Обычный запуск:

```bash
docker compose up -d --build
```

Кабинет: http://localhost:3002/. Админка: http://localhost:3002/admin_login.html.
Первый администратор создаётся только при отсутствии администраторов в базе.
Изменение `ADMIN_PASSWORD` в `.env` не меняет пароль существующего аккаунта:
используйте смену пароля в админке.

## Режим разработки

```bash
docker compose -f compose.yaml -f compose.dev.yaml up -d --build
```

При следующих запусках готового образа `--build` можно убрать.

| Что изменили | Действие |
|---|---|
| HTML, CSS, браузерный JavaScript, переводы | Обновить вкладку; при переходе в dev — Ctrl+Shift+R |
| Подключённый серверный JavaScript | Node.js перезапускается автоматически |
| SQL-миграции и файлы, читаемые сервером с диска | Перезапустить приложение |
| Зависимости или Dockerfile | Повторить запуск с `--build` |
| `.env` или Compose | Повторить команду запуска |
| Обстановку через редактор | Сохранить и опубликовать шаблон |

`compose.dev.yaml` подключает `src`, `scripts`, `database`, `public` из рабочей
папки. Код редактируется на компьютере. Загруженные файлы внутри `public`
хранятся в отдельных записываемых Docker-томах, которые имеют приоритет над
одноимёнными папками исходников. Пересборка не обновляет содержимое таких томов.

Полезные команды для режима разработки:

```bash
docker compose -f compose.yaml -f compose.dev.yaml ps
docker compose -f compose.yaml -f compose.dev.yaml logs --tail=100 app
docker compose -f compose.yaml -f compose.dev.yaml restart app
curl --fail http://localhost:3002/api/ready
```

Ожидаемый ответ: `{"status":"ready"}`. Серверный перезапуск кратко обрывает
соединения участников. Автоматического обновления вкладки нет.

## Переход с прежнего локального запуска

Текущую базу заново импортировать не нужно. Новый Compose сохраняет имя проекта
`virtual-world-local` и имена всех прежних томов PostgreSQL 18 и приложения.
В `.env` должен остаться **пароль существующей базы**: старый локальный Compose
задавал `local_virtual_world_only`. Укажите также адрес сайта и настройки
администратора. Уже существующие администраторы сохраняют прежние пароли.

Из корня той же рабочей папки выполните команду dev-запуска выше. Она переключит
приложение на новую конфигурацию с прежними данными. Старые файлы
`docker-compose*.yml` больше не нужны.

## Хранение данных

PostgreSQL, модели, изображения, загрузки и секреты авторизации сохраняются
в Docker-томах. Git хранит исходники. Новая установка получает базовый шаблон;
ваша отредактированная мебель и комнаты переносятся отдельно с базой и файлами.

`docker compose stop` останавливает сервисы. `docker compose down` удаляет
контейнеры, сохраняя тома. **Не выполняйте `down -v` для рабочей установки:**
это удалит базу и загруженные файлы. Смена `DB_PASSWORD` в `.env` сама по себе
не меняет пароль уже созданного пользователя PostgreSQL.
