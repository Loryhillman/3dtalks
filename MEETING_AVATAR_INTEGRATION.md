# Человеческие аватары по умолчанию и рот по голосу

21 октября 2026. Ветка `codex/meeting-avatar-integration` от `b86dc753`.
Поручение пользователя: перенести проверенную анимацию в переговорную,
сделать человеческие модели стандартными вместо примитивных фигур и по
возможности добавить мужчину нейтральной азиатской внешности. Стиль —
стилизованный человек без сильной мультяшности. LiveKit пока отложен.

## 1. Анимация в существующей переговорной — реализовано

`avatarAudioSignal.js` — общая огибающая для стенда и переговорной. Анализирует
каналы уже декодированного AudioBuffer без копирования PCM; сохраняет только
огибающую по 20-мс окнам. Максимум два канала, 96 кГц, 61 секунда (нынешний
голосовой лимит допускает хвост кодека), конечные значения. Стерео считается
по энергии, без взаимного погашения. Повреждённый/неподдерживаемый сигнал
отключает только анимацию, не воспроизведение.

`voiceChat.js` связывает конкретный BufferSource с characterId и текущим
экземпляром группы участника, AudioContext и фактическим source.start(t0).
Рот открывается при слышимом воспроизведении, а не при приходе VOICE_STATE.
При нынешнем PTT это происходит после того, как собеседник закончит запись.
Для собственного голоса не добавляются второй микрофон или прослушивание себя.

`meetingMouthAnimation.js` выполняется в существующем MeetingFrame после
скелетной анимации и посадки, перед render. Дополнительных rAF/таймеров нет.
Для каждого меша используется viseme_aa, иначе jawOpen, без сложения двух
открывающих форм. Меши зубов/языка с соответствующей формой также участвуют.
Если у загруженного пользовательского аватара нет этих форм, он остаётся
статичным. Костная челюсть и фонетический lip-sync сюда не входят.

Каждый участник имеет независимые веса; при перекрывающихся источниках берётся
максимум, а не сумма. До 16 источников анимации. Окончание/ошибка source, mute,
выход и отмена звука очищают веса/ссылки. При suspension или hidden вес нулевой.
Удаление участника очищает привязки, повторный вход не наследует старую речь;
запоздалый decode проверяет исходную группу. Смена/завершение загрузки GLB
инвалидируют кеш morph-мишеней. Настройки и протокол сервера не расширяются.

Проверки:

- `test-meeting-mouth-animation.js`: независимые участники, паузы, bounds,
  suspension/hidden, поздняя модель, несколько источников, removal/rejoin/reset.
- `test-meeting-mouth-browser.js`: настоящие AudioContext/decode/BufferSource
  и voiceChat в Chromium, тон/тишина/тон, mute, поздний decode после rejoin.
  Участники/лицевые меши — фикстуры, транспорта WebSocket в этом тесте нет.
- Регрессия: voice lifecycle, meeting render loop/participants,
  `test-meeting-startup-browser.js --builtin-v2`, оба теста стенда.

Это проверяемая инфраструктура анимации, ещё не готовый новый стандартный аватар.
На сайте до поставки моделей примитивные фигуры сами по себе не получают губы.

## 2. Подготовка стандартных моделей — комплект кандидатов подготовлен

Нынешний MPFB-образец: 29 МиБ и 83 686 треугольников. Он остаётся техническим
эталоном; включать шесть его копий стандартом без оптимизации нельзя.
По следующему поручению подготовлены мужчина азиатской внешности и женский
вариант: 3,2/3,7 МиБ, 35 580/37 588 треугольников, реальные рот/посадка и
шесть независимых экземпляров проверены в Chromium. Файлы и лицензии —
public/assets/avatars/meeting-human-v1. Отчёт, ограничения и повторение —
[MEETING_HUMAN_V1.md](docs/research/avatar-lipsync/MEETING_HUMAN_V1.md).
Кандидаты доступны в локальном стенде; default аккаунта ещё не заменён.

Основной кандидат процесса подготовки — MPFB: можно настроить человеческую
внешность, подготовить экспортную копию с лицевыми формами, убрать скрытую
геометрию под одеждой и лишние subdivision. Это возможность инструмента,
а не доказательство готовности конкретного персонажа. Официальные источники:

- [Создание персонажа](https://static.makehumancommunity.org/mpfb/docs/characters/creating.html).
- [Экспортная копия и лицевые формы](https://static.makehumancommunity.org/mpfb/docs/exporting/export_copy.html).
- [Лицензии MakeHuman](https://static.makehumancommunity.org/about/license.html).
- Запасной каталог — [Microsoft Rocketbox](https://github.com/microsoft/Microsoft-Rocketbox):
  требует проверки конкретного персонажа, конвертации и визуального соответствия.

Для каждого включаемого файла сохранить исходник/версию/URL/лицензию,
отдельные лицензии волос, одежды и текстур, SHA-256 оригинала и результата,
повторяемые операции подготовки. Не выводить коммерческие права только из
лицензии редактора. Никаких покупок/учётных записей внешнего сервиса без запроса.

Изначальные целевые бюджеты: до 8 МиБ GLB, примерно
25 тысяч треугольников, текстуры до 1024px; mouth target и нейтральная форма,
совместимый humanoid-скелет и проверенная посадка. Проверить рот/зубы в анфас
и профиль, одежду при посадке, глаза/масштаб головы. Внешность оценивается
визуально; название файла не служит доказательством соответствия пожеланию.

Приёмка — шесть видимых персонажей в стандартной комнате, реальные morphs,
отсутствие разделяемых изменяемых весов между экземплярами, холодная/повторная
загрузка и очистка ресурсов. Зафиксировать браузер/устройство/размеры/FPS/
draw calls/память. Числа полигонов сами по себе не доказывают производительность.
Подготовленный комплект укладывается в размер; ориентир 25k не достигнут.
Сохранены лицо/кисти/зубы. Проверка шести GLB — отдельная сцена на SwiftShader,
не измерение полной комнаты на реальном телефоне; этот пункт приёмки остаётся.

## 3. Каталог и выбор стандартного аватара — после подготовки ассетов

Стандартный аватар должен приходить из серверного allowlist-каталога с
версионированным идентификатором, локальным URL и проверенными метаданными
скелета/рта. Хранить канонический GLB в репозитории/поставляемом комплекте,
не во временном /tmp и не на внешнем CDN. Не создавать поддельный пользовательский
assetId и не обходить проверку владения личными моделями.

Для аккаунтов без собственного оформления выбирать человеческий builtin;
выбор сделать доступным в кабинете аватара с предпросмотром. Явно сохранённые
пользовательские модели/головы/изображения сохраняются. Старый точный стандартный
конфиг можно трактовать как прежний default без перезаписи данных, но решение
должно быть единым для API, WS, кабинета, редактора мест и /play.
Точный DTO и валидацию закрепить перед реализацией этапа; текущий mode:full
требует принадлежащий аккаунту asset, поэтому простой подмены пути недостаточно.

Во время загрузки — нейтральная заглушка; ошибка встроенного GLB должна быть
видна пользователю с возможностью повторить загрузку. Прежнюю фигуру можно
оставить аварийной заглушкой, но не штатной внешностью. Отдельно проверить
редактор и точки посадки, чтобы новый стандарт не остался только в /play.

## 4. Общая приёмка и поставка

Два аккаунта: стандарт/мужской вариант/своя модель, смена места, речь каждого,
паузы, параллельное воспроизведение, mute, переподключение, выход/история браузера,
поздние загрузки, разные комнаты, мобильный экран. Приёмка физическими микрофонами
по HTTPS дополняет тестовые API и синтетический звук. Только после этого
называть интеграцию моделей готовой. Push и VPS требуют отдельного поручения.
