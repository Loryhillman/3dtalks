# Page Templates & Content Guidelines

## Унифицированные секции страниц
1. Breadcrumbs (если навигационно необходимы).
2. PageHeader: ясный заголовок H1 и короткое описание; рядом одно основное действие.
3. Toolbar (только если нужен): Search → Filters → Sort → дополнительные операции.
4. Content: Grid/Data/Form/Workspace согласно [layout.md](layout.md).
5. Feedback: loading/empty/error/success/offline, см. [patterns.md](patterns.md).

Нельзя рисовать пустые элементы ради соответствия шаблону; зона появляется только при реальной необходимости.

## Примеры шаблонов
- **Grid:** «Мои комнаты» с RoomCard; каталог шаблонов — запланированная возможность, не считать реализованной.
- **Data:** будущие пользователи/история с таблицей и mobile fallbacks.
- **Form:** настройки, редактирование данных, разделение по смыслу и Save/dirty guard.
- **Workspace:** будущий редактор инструментов; не требует изменений Three.js без отдельного согласования.

## Tone of Voice
- Профессионально, кратко, нейтрально, без шуток, эмоциональных междометий и технических traceback для пользователя.
- Название кнопки = действие: «Создать комнату», «Сохранить изменения», «Войти в комнату», «Удалить комнату», «Завершить встречу», «Повторить», «Отмена».
- Сообщение об ошибке: что произошло + что можно сделать, без необоснованных обещаний.
- Предупреждения об удалении зависят от фактических последствий, подтверждённых backend.

## RU/EN — обязательная локализация
- Новые видимые строки проходят через **существующую** систему i18n; её фактическое имя определить аудитом.
- Нельзя hard-code один язык в новом UI, если приложение предусматривает переключение.
- Переводятся: кнопки, формы, labels, accessible names, title/alt, ошибки, Toast, пустые состояния, подтверждения.
- Смена языка не ломает навигацию и не сбрасывает пользовательские данные.
- Проверить длинные переводы, переносы и масштабирование текста; не ограничивать высоту кнопок так, что перевод обрезается.

## Контроль качества контента
- Сообщения содержат полезные инструкции, не «Что-то пошло не так» без дальнейших действий.
- Нет «dummy» ссылок, кнопок, фальшивых счётчиков/статусов или видимых функций, которых backend не поддерживает.
- Скрытые недоступные разделы не используются как работающая навигация.
- Поддерживаются состояния «нет данных» и «нет результатов поиска».
