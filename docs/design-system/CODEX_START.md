# Инструкция по подключению дизайн-системы к 3DTalks

## 1. Подготовка
1. Сделайте резервную ветку/коммит существующего проекта.
2. Распакуйте содержимое архива **в корень репозитория 3DTalks** с сохранением каталогов `docs/design-system/`.
3. **Проверьте существующий `AGENTS.md`.** Если он есть, не перезаписывайте: объедините нужные правила из вложенного файла вручную или поручите Codex анализ и аккуратное слияние.
4. При наличии `DESIGN_SPEC.md` оставьте его как историческую спецификацию редизайна; он не замещает новую дизайн-систему.
5. Убедитесь, что структура документации доступна Codex в рабочем каталоге.

## 2. Первый запрос к Codex — только аудит

```text
Изучи AGENTS.md и всю документацию docs/design-system/.
Нужно внедрить дизайн-систему 3DTalks постепенно, без масштабного рефакторинга.
Начни ТОЛЬКО с этапа 0 из docs/design-system/integration.md — аудита существующего frontend.
Определи стек, реальные файлы компонентов, дизайн-токены, маршруты, локализацию и тестирование.
Сопоставь фактический UI с утверждёнными правилами. Укажи риски и расхождения.
Подготовь план следующих минимальных этапов и список конкретных файлов.
Не меняй код, не создавай новые компоненты, не устанавливай зависимости.
Не затрагивай Three.js, API, авторизацию и бизнес-логику.
Дождись моего подтверждения перед изменениями.
```

## 3. После получения отчёта
Проверьте вывод Codex и разрешайте изменения по одному этапу: (1) документация/AGENTS, (2) семантические токены и контрастность, (3) реестр существующих компонентов, (4) локальная унификация по необходимости, (5) тестирование. После каждой UI-задачи требуйте отчёт Design QA.

## 4. Контроль при импорте
- Путь `docs/design-system/README.md` существует.
- Все 14 документов в каталоге присутствуют.
- Нет потерь в старом AGENTS.md.
- `component-registry.md` пока без выдуманных путей (значения TBD намеренны).
- Актуальные CSS/компоненты не менялись одной лишь распаковкой документов.
