# Layout System

## App Shell — неизменный каркас
Обычные страницы используют **левый Sidebar** и **верхний Header**, затем внутренние зоны Page Header → опциональный Toolbar → Content Area → опциональный Context Panel.

| Часть | Правило |
|---|---|
| Sidebar expanded | 248 px, закреплён слева |
| Sidebar collapsed | 64 px, только иконки с доступными названиями/tooltip |
| Header | 64 px, `sticky`, не перекрывает контент |
| Main | оставшееся пространство; отступ 32 px на десктопе |
| Карточные сетки | до 3 колонок в широкой области, 16:9 для превью комнат |
| Context Panel | только при функциональной необходимости; не рисовать пустую |

Состояние свёрнутости Sidebar сохраняется между обновлениями страницы в рамках текущего существующего механизма приложения; storage-способ определить по аудиту. Header: переключение Sidebar, навигационный контекст, язык и профиль; не добавлять мнимые функции (колокольчик/глобальный поиск). Переключатель RU/EN и logout обязаны сохранить текущую функциональность.

## Четыре разрешённых шаблона
1. **Grid Page:** каталоги комнат/шаблонов/моделей; заголовок, primary action, опциональные фильтры, адаптивные карточки, empty/loading/error.
2. **Data Page:** таблицы пользователей/приглашений/истории; сортировка, постраничность при необходимости; компактный мобильный список без потери данных.
3. **Form Page:** настройка аккаунта и сложные формы; разделы, чёткие подписи, ограничение длины строки, primary Save и dirty guard.
4. **Workspace Page:** будущие инструменты и редакторы; центральная рабочая область, согласованные инструментальные панели; адаптированные mobile-панели. Данный шаблон **не даёт разрешения редактировать Three.js**.

Новый шаблон — принципиальное расширение; требуется согласование и запись в CHANGELOG.

## Dashboard /rooms: нормативный пример
- Заголовок «Мои комнаты», количество комнат, кнопка «Создать комнату».
- Карточка: 16:9 статическое превью шаблона, fallback, название, статус, занято/вместимость, основной «Войти в комнату», быстрое «Приглашение», контекстные действия (`···`).
- Контекст: переименовать, закрыть/открыть вход, завершить встречу, удалить; действия строго по реальным правам/API.
- Создание: модальное окно (название, лимит, выбор доступного шаблона). Если backend не поддерживает выбор — показать только действительно работающее решение, не имитировать варианты.
- Вход по приглашению отдельной секцией, без изменения обработки ссылок.
- При пустом списке — Empty State; ошибка сервера не уничтожает ранее загруженные карточки.

## Правила размещения
- Не дублировать первичное действие на одной визуальной ступени.
- Не добавлять пустые Toolbar, Panel, Sidebar links.
- Длинные формы имеют контролируемую ширину; таблицы — читаемую ширину и горизонтальный скролл только внутри таблицы при обосновании.
- Layout Tokens, а не магические числа, кроме мотивированного исключения.
- Проверять с увеличением текста 200%, узкими окнами, сменой языка.

## Мобильный App Shell
До 767 px Sidebar становится drawer, открывается по кнопке, закрывается кликом вне/через Esc, корректно управляет фокусом. Header компактнее по содержанию, высота может адаптироваться лишь при необходимости читаемости без нарушения базовой нормы. Подробнее: [responsive.md](responsive.md).
