## Метод заполнения
1. Найти реальный стек (React/Vue/vanilla JS и т. п.), роутер, CSS-организацию и библиотеки.
2. Установить реальные пути определения, экспорта и использования каждого компонента.
3. Зафиксировать вариации и дубли, используемые токены, тесты, доступность, связь с локализацией.
4. После проверки назначить статус **Stable** только если контракт документирован, текущая реализация соответствует требованиям и проверена. Иначе указать gap, Experimental/Deprecated только с обоснованием и согласием.
5. Вносить изменения в реестр в одной задаче с соответствующими кодовыми изменениями, но не предлагать вымышленные компоненты.
