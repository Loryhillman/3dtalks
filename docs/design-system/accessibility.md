# Accessibility — WCAG 2.2 AA

**Статус:** обязательная цель и критерий приёмки веб-интерфейса. Наличие правил или успешный axe-тест не равно подтверждённому полному соответствию WCAG.

## Контраст и семантические цвета
- Текст обычного размера — контраст не менее 4.5:1; крупный — не менее 3:1.
- Значимые нефоновые UI-границы/иконки — не менее 3:1 относительно соседних цветов.
- Видимый keyboard focus обязателен; выполнить правила WCAG 2.2 AA для focus appearance/obscured в применимых сценариях.
- Токен `#00A878` + белый текст **нельзя** использовать как основную кнопку без исправления: контраст пары ниже 4.5:1.
- Вторичный текст `#8292A3` на белом также проверять и при необходимости заменить доступным семантическим токеном.
- Изменять можно семантические пары для доступности, сохраняя брендовые примитивы. Результаты контрастных измерений записывать в QA-отчёт.

## Клавиатура и фокус
- Полный основной сценарий выполняется без мыши: Tab/Shift+Tab, Enter/Space, стрелки в соответствующих составных компонентах.
- Tab order следует логике страницы; никакой keyboard trap вне модальных окон.
- Диалог: initial focus, focus containment, возврат focus после закрытия; Esc закрывает там, где нет потери данных (dirty guard имеет приоритет).
- Skip link для перехода к основному контенту; навигация семантически размечена.

## Семантика и объявления
- Native semantic HTML, label/controls, именованные icon-only buttons.
- Ошибки ассоциируются с полями (`aria-describedby`, `aria-invalid` и эквивалент), не только Toast.
- Toast/Alert передают изменения без чрезмерных live region повторов; значимые обновления должны быть понятны screen reader.
- Изображения-превью: содержательное alt, если несут информацию, иначе декоративные.
- Статус комнаты передаётся словом/иконкой, не только цветом.

## Responsive, touch, motion
- Проверить resize/reflow при узком viewport и увеличении текста до 200%; не скрывать функциональность.
- Минимальные target sizes WCAG 2.2 AA по применимым исключениям; стандарт продукта — целевые 44×44 px для touch.
- Нет hover-only операций; интерфейс работает при reduced motion и без анимаций.

## Алгоритм тестирования
1. Проверить реально используемые пары цветов измерителем контраста.
2. Пройти сценарий клавиатурой, включая модальные окна и dropdown.
3. Выполнить axe-core/аналог при наличии, собрать конкретные findings.
4. Провести ручную проверку фокуса, текстового zoom, RU/EN, мобильного touch.
5. Закрыть блокирующие проблемы; оставшиеся явно указать в отчёте.

**Вне области:** аудит доступности рендеринга сцены Three.js и управления персонажем, если это отдельно не заказано.
