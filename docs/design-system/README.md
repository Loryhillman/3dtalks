# 3DTalks Design System

**Версия:** 1.2.0 (библиотека материалов приведена к единому оформлению)
**Статус:** approved specification / implementation unverified
**Область:** обычный веб-интерфейс управления виртуальными переговорными. **Не распространяется на Three.js-сцену, графику и управление аватарами внутри 3D.**

## Статус внедрения в репозитории

Текущие границы, подтверждённые исходники, расхождения и порядок следующих
этапов — в [implementation-status.md](implementation-status.md). При применении
общих правил учитывайте эти ограничения проекта. Токены подключены совместимо с текущим кабинетом;
результаты — в [token-integration.md](token-integration.md). Библиотека материалов обновлена —
[результат и QA](materials-redesign.md). Управление показом и увеличенный экран
ещё не обновлены; соответствие всего интерфейса стандарту не подтверждено.

## Цель
Единый, долговременный стандарт Light Premium SaaS / Soft Minimal для всех нынешних и будущих страниц 3DTalks. Документируем утверждённое поведение, а не выдаём запланированные функции за готовые. Требования из ранее согласованного [DESIGN_SPEC.md](../../DESIGN_SPEC.md) сохраняют силу для завершённого редизайна; при конфликте проверить фактический код и согласовать корректировку стандарта, не разрушая бизнес-логику.

## Шесть неизменных принципов
1. **Clarity First:** ключевые действия очевидны; второстепенные не затмевают основные.
2. **Visual Consistency:** использование одной системы токенов и компонентов.
3. **Progressive Disclosure:** дополнительные настройки показываются по запросу.
4. **Predictable Interaction:** одинаковые действия работают одинаково.
5. **Responsive by Default:** мобильная версия, клавиатура и доступность проектируются сразу.
6. **Scalable Architecture:** компоненты переиспользуются, новые стили вводятся контролируемо.

## Принятие новых решений
- **Разрешено без согласования:** применение уже существующих шаблонов, паттернов и компонентов в рамках задачи.
- **Требуется согласование:** новый визуальный паттерн, принципиально новый компонент, токен с новой семантикой, глобальный layout, новая анимация, несовместимое изменение.
- **Не входит в область автономного редизайна:** бизнес-логика, API, авторизация, Three.js, новые продуктовые возможности.
- Перед реализацией агент проверяет актуальный код. На текущем этапе структура фронтенда, имена компонентов и наличие библиотек **не подтверждены**.

## Принцип завершения
После **каждой UI-задачи**: визуальная, функциональная, адаптивная, доступная и RU/EN проверка; честный отчёт о том, что выполнено, что не проверено и какие риски остались. См. [qa.md](qa.md).
