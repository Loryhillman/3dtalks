# Управление показом и увеличенный экран — Design QA

Дата: 2026-10-20. Версия дизайн-системы: 1.3.0.
Этап: оформление существующих RoomPresentation и RoomScreenPreview.

## Реализация

Панель владельца использует `.meeting-ui.room-presentation-dialog`, общий Inter,
Button variants и tokens из app-controls.css. Заголовок/имя комнаты отделены
от прокручиваемого body. Раздельно показаны текущий материал и страница,
выбор следующего материала, состояние библиотеки и обратная связь команды.
Полное имя выбранного файла также выводится под native select и связано
через aria-describedby; длинные имена не теряются за обрезкой поля.

- Начать показ — primary; страницы — нейтральные кнопки; остановка — destructive.
- Показываются загрузка/пустая библиотека/ошибка и явный Retry. Изменение общего
  состояния не затирает ошибку загрузки списка. Изначально выбирается текущий
  asset, если он найден среди готовых материалов; позднее выбор принадлежит пользователю.
- Команды/выбор блокируются при ожидании подтверждения и sync; отсутствие
  state/права/соединения также блокирует отправку. Close остаётся доступен.
- Сохраняются requestId, expectedEpoch, expectedRevision, тайм-ауты, WS-результаты,
  серверная авторизация и отсутствие offline queue/автоматического replay.
  Коды локальных ошибок timeout/disconnect сохраняют точную надпись в новом feedback.
- При потере canControl или ответе списка 401/403 панель закрывается; запрос
  списка отменяется. После закрытия фокус возвращается к доступному trigger
  либо к кнопке переговорной. Закрытие панели не останавливает общий показ.
- live region текущего материала/страницы обновляет текст только при изменении;
  feedback команды и статус загрузки библиотеки — отдельные области.

Увеличенный экран использует `.meeting-ui.room-screen-preview` и отдельный
`public/css/room-screen-preview.css`, подключённый в index.html и room_editor.html.
Он содержит header, локальную панель масштаба, прокручиваемую область и краткую
подсказку. App Shell и стили всей страницы не подключаются.

- Масштаб 50–300%, шаг 25%, 100% означает подгонку содержимого под область,
  как и прежний начальный масштаб, а не один CSS px на пиксель canvas.
- «По размеру окна» возвращает 100% и начало прокрутки. ResizeObserver повторно
  подгоняет базовый размер при изменении области, сохраняя выбранный коэффициент.
- Область доступна через Tab и прокручивается стрелками. Escape/Tab/возврат
  фокуса и изоляция pointer/keyboard/wheel/touch сохраняются.
- Canvas получает описание содержимого, а не постоянную подпись тестовой сетки.
  Live refresh копирует общий экран; локальный zoom/fit/pan не отправляет WS-команд.
- При закрытии ResizeObserver отключается, DOM удаляется, размеры копии canvas
  обнуляются. Исходный canvas и GPU принадлежат сцене. При source нулевого размера
  новое окно не открывается, а активный просмотр такого source закрывается.

HTML/CSS и локальные состояния UI изменены; схемы БД, серверные маршруты,
wire protocol, PDF parser/worker и рендеринг сцены не менялись. Внешняя панель
переговорной и чат сохраняют прежнее оформление; это не полный редизайн /play.

## Запущенные проверки

```sh
node --check public/js/roomPresentation.js
node --check public/js/roomScreenPreview.js
node scripts/test-room-presentation-browser.js
node scripts/test-room-screen-browser.js
node scripts/test-room-materials-browser.js
node scripts/test-meeting-ui-browser.js
node scripts/test-meeting-startup-browser.js --builtin-v2
node scripts/test-room-presentation-protocol.js
```

- PASS Visual: просмотрены desktop/mobile панели и viewer, а также новый
  viewer в настоящем редакторе с тестовым офисом. Общие tokens и native controls.
- PASS Functional: реальный локальный PDF worker, страницы/изображение, live
  canvas, pending/result/conflict/timeout, retry, empty/loading/401, role loss,
  остановка, disconnect и запоздалые ответы. Protocol test также прошёл.
- PASS Responsive: RU/EN/zh-CN, 320×568, 375×812, 430×932, 768×1024, 1280×800,
  1920×1080, 844×390; bounds и отсутствие горизонтального переполнения dialog.
  В viewer прокручивается только frame. В редакторе проверены 375×812 и 1280×800.
- PASS Accessibility (проверенные части): клавиатура/focus, возврат после Escape,
  fit, ArrowRight для увеличенного canvas, 44×44 Close, контраст актуальных
  текстовых пар панели >=4.5:1. Частичная CSS-проверка увеличенного текста 200%
  для панели при 320×568. Закрытие освобождает ResizeObserver — проверено счётчиком.
- PASS Localization: подписи panel/viewer, RU/EN/zh-CN, полное имя материала.
- PASS Regression: редактор сохраняет выбранный объект и публикацию; полный
  startup со стандартной GLB-комнатой/экраном сохранил посадку/камеру и однократный
  GPU dispose. Материалы, HUD, чат/голосовые обработчики проверены прежними сценариями.
- PASS: syntax, локальные Markdown-ссылки, покрытие новых i18n ключей и git diff --check.

## Ограничения

Проверки используют настоящие browser scripts, Chromium, PDF/GLB/canvas и
тестовые HTTP/WS API. Это не live-тест серверной авторизации или общей базы.
NOT RUN: рабочая PostgreSQL/VPS, два реальных пользователя и микрофоны, Safari,
реальные сенсорные устройства/safe areas/экранная клавиатура, axe и screen reader,
полный WCAG-аудит и системный browser zoom. CSS 200% проверен частично, а не на
всех комбинациях обоих окон. Новых зависимостей нет; отдельная Vite/TypeScript
сборка не запускалась для напрямую обслуживаемых browser scripts.
Переключение языка проверено между открытиями окон; динамический перевод уже
открытого окна отдельно не заявляется. Docker, push и развёртывание не выполнялись.

## Ручная приёмка

Владелец: открыть управление показом, выбрать PDF/изображение, начать, сменить
страницу и закрыть панель. Другой участник должен продолжать видеть показ;
кнопок управления у него нет. Проверить настоящее обновление состояния при
конфликте двух окон владельца и повторное подключение.

Увеличить экран, изменить размер окна/ориентацию, масштаб, прокрутку и нажать
«По размеру окна». Слайд остаётся общим, масштаб — личным. Escape возвращает
фокус; закрытие/выход из комнаты освобождают просмотр. В редакторе проверить
просмотр тестовой сетки и сохранность выбранного объекта.

Этап окон завершён для пользовательской проверки. Расширение редизайна на HUD,
чат и другие части переговорной, push и развёртывание согласуются отдельно.
