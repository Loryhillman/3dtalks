# UX Patterns

## 1. Создание и редактирование
- Короткие формы: Dialog; большие формы: Form Page; сложные редакторы: Workspace Page.
- Перед submit: клиентская валидация + серверная проверка; ошибки поля рядом с полем.
- Во время запроса: loading, защита от двойной отправки.
- При успехе: закрыть окно/сбросить dirty → обновить затронутые данные → success Toast.
- При ошибке: не очищать форму; показать причину и доступное повторное действие.

## 2. Явное сохранение и dirty guard — нормативный стандарт
- По умолчанию **нет автосохранения**. Использовать «Сохранить» или «Сохранить изменения».
- Dirty определяется относительно последнего подтверждённого сервером состояния, а не простого локального нажатия.
- При закрытии диалога, внутренней навигации или уходе из формы с dirty показать подтверждение: «Продолжить редактирование» / «Выйти без сохранения».
- Для закрытия вкладки применять доступный браузерный `beforeunload` механизм, где поддерживается; не обещать кастомное содержимое браузерного диалога.
- После отказа от выхода данные остаются. При ошибке сохранения dirty не сбрасывается.
- Автосохранение — исключение только после согласования конкретного сценария.

## 3. Опасные действия
- Для удаления комнаты и завершения встречи — обязательный Dialog с названием комнаты и **проверенным** описанием последствий.
- Destructive button красная, label точно называет действие, отмена вторична; операция не исполняется до подтверждения.
- На loading блокировать повторное подтверждение; ошибку показывать в диалоге; на успех закрыть и обновить список.
- Нельзя утверждать, что удаление «навсегда», не проверив backend; предупреждения должны быть фактически корректными.

## 4. Feedback
| Тип | Место | Длительность |
|---|---|---|
| Success Toast | Справа снизу | 4 с |
| Info Toast | Справа снизу | 5 с |
| Error Toast | Справа снизу | до ручного закрытия |
| Persistent Offline Alert | Видимая область без перекрытия критичных действий | пока проблема сохраняется |

Не более трёх Toast одновременно, очередь для остальных. Не дублировать каждую ошибку поля Toast-ом. Важные сообщения должны быть доступны экранным дикторам.

## 5. Работа с данными
- Начальная загрузка: Skeleton, похожий на будущий контент.
- Нет объектов: EmptyState с ясным CTA; ничего не найдено по фильтру — другой EmptyState с очисткой фильтра.
- Повторная загрузка: сохранять предыдущий результат, рядом показывать актуальность/индикатор.
- Ошибка запроса: Retry, сообщение без технического стека и raw API secrets.
- Ограничение количества комнат: объяснить лимит; не предлагать запрещённое действие.

## 6. Потеря соединения
- Ранее успешно загруженные карточки остаются видимыми и помечаются как потенциально устаревшие.
- Локальные вводы формы сохраняются. При подтверждённом offline серверные действия ограничиваются.
- После восстановления связи — обновление/сверка; не подменять server truth устаревшим локальным состоянием.
- Изменяющие запросы не повторять автоматически, если невозможно гарантировать отсутствие дублей (idempotency).
- Network status нельзя считать доказательством успешного сервера; фактический результат определяется запросами.

## 7. Поиск и фильтры
Порядок в Toolbar: поиск → фильтры → сортировка → остальные действия. Состояние «нет совпадений» не равно «нет данных». Ручная очистка фильтров доступна клавиатурой и touch.

## 8. Модальные окна и focus
Внутренние диалоги не должны скрывать критичные сообщения; focus trap и возврат focus после закрытия. На мобильном длинный Dialog допускает полноэкранное представление.
