# Редизайн библиотеки материалов — Design QA

Дата: 2026-10-20. Версия дизайн-системы: 1.2.0.
Завершённый этап: RoomMaterials в кабинете и HTML-панели переговорной.

## Что изменилось

- Один светлый native dialog вместо двух оформлений. Desktop: библиотека
  слева, приватный canvas preview справа; до 767 px — одна колонка.
- Заголовок и имя комнаты отделены, закрытие доступно вне прокручиваемого
  содержимого. Upload target, форматы/лимиты, реальные квоты с meter,
  состояния файлов, явные действия и выбранный материал сгруппированы.
- Подтверждение удаления внутри того же dialog; на время вопроса скрыто
  содержимое библиотеки. Фокус начинает с «Отмена»; Escape отменяет вопрос,
  повторный Escape закрывает библиотеку. При закрытии незавершённый вопрос
  разрешается отказом; не остаётся ожидающего Promise.
- MATERIAL_IN_USE по-прежнему требует отдельного подтверждения остановки
  и stopShowing/requestId/expectedEpoch/expectedRevision. API не менялся.
- Во время операций кнопки и file input блокируются, Close и Cancel upload
  остаются доступны по соответствующему сценарию. Фокус после отмены
  восстанавливается к действию, после удаления — к доступному fallback.
- Ошибки видны в панели, Retry выполняется через «Обновить»; неудачное
  обновление сохраняет строки. Начальная ошибка больше не оставляет
  вечный Loading. Ответы 401/403 закрывают библиотеку и запускают очистку.
- Canvas скрыт при смене документа; stale completion не возвращает старый
  материал. Смена сессии, закрытие, disconnect контроллера презентации
  сохраняют отмену и очистку. Локальный preview не управляет общим экраном.
- Все новые подписи добавлены в RU/EN/zh-CN. Иконки PDF/IMG декоративны;
  имя, состояние и действия остаются текстовыми.

## Общие стили и область действия

`public/css/app-controls.css` выделяет существующие native Button variants
и Inter из app-ui.css. Он импортирует app-tokens.css и используется app-ui.css
и room-materials.css. Селекторы `:where(.app-ui, .meeting-ui) .ui-button`
имеют низкую специфичность, чтобы локальные варианты/размеры не терялись
при повторном CSS import. Общие font/link defaults в app-ui.css также
имеют низкую специфичность: они не должны затирать weight и цвет primary link.

`.meeting-ui` применяется **к самому dialog**, включая кабинет; это область
токенов и controls, а не новая оболочка страницы. app-ui.css/app-shell.css
в переговорную не добавлялись. Никаких глобальных reset или motion overrides,
изменений Three.js, renderer, камеры, backend, схемы БД и протокола нет.
Файлы CSS/JS панели получили новые query versions в существующих HTML.
Панель управления показом и RoomScreenPreview пока не переработаны.

## Ограничения и ручная проверка

Локальное окружение проверок: Node.js 22.22.2 и установленный Chromium.
Отдельная Vite/TypeScript-сборка не запускалась: изменённые browser scripts
обслуживаются напрямую и проверены в реальном Chromium.

NOT RUN: axe, полный WCAG-аудит, screen reader, Safari, реальные touch-устройства,
экранная клавиатура/safe areas, live-проверка с рабочей PostgreSQL и двумя
пользователями. CSS-увеличение текста не равно проверке browser zoom на каждом
устройстве. Начальная загрузка показана текстом; skeleton строки не добавлены.
Динамический перевод уже открытой панели при смене языка отдельно не проверен:
подтверждено открытие на каждом выбранном языке.

Docker/VPS не запускались, push/развёртывание не выполнялись. Проверки используют
реальные клиентские модули и GLB/PDF/canvas, но тестовые API/WS; они не заменяют
ручную проверку пользовательской базы и реальных материалов.

Для приёмки: открыть библиотеку из карточки и через управление показом;
загрузить PDF/изображение, проверить длинные имена и квоты, страницы, отмену
удаления и активный показ. На телефоне прокрутить до preview и навигации.
Закрытие библиотеки не должно завершать общий показ. Проверить реальный upload
и удаление с серверной авторизацией перед следующим развёртыванием.

Следующий согласуемый этап — оформление управления показом и увеличенного
экрана, с проверкой второго потребителя ScreenPreview в редакторе.
