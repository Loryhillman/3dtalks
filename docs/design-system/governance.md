# Governance & Codex Rules

## Режим автономности
Codex самостоятельно выполняет порученную задачу, если использует утверждённые шаблоны, паттерны, токены и существующие компоненты. **Новый принципиальный компонент, стиль, шаблон, анимация, глобальный App Shell или несовместимый контракт требует предварительного согласования.** Согласования не нужны на каждую тривиальную правку.

## Алгоритм агента
1. Прочитать `AGENTS.md`, `README.md` и целевые разделы дизайна.
2. Изучить фактический репозиторий, компоненты, маршруты, i18n, API и тесты.
3. Установить границы задачи, переиспользуемые компоненты, риски для бизнес-логики.
4. При необходимости нового визуального паттерна — proposal (причина, варианты, токены, состояния, responsive, accessibility, migration); **остановиться и ждать согласования**.
5. Реализовать минимальное изменение, не менять backend/Three.js/API без отдельного задания.
6. Выполнить применимый Design QA и честно отчитаться.
7. Для утверждённых изменений стандарта обновить спецификацию, component-registry, версию и CHANGELOG.

## Semantic Versioning отдельно от продукта
- MAJOR: несовместимые правила/API компонента или токены.
- MINOR: совместимые новые компоненты/варианты/возможности.
- PATCH: исправления, уточнения и обратносовместимые мелкие коррекции.
- Номер документации фиксируется в `README.md` и `CHANGELOG.md`, не предполагает привязку к версии приложения.

## Lifecycle компонентов
- **Experimental:** одобрен для ограниченного сценария; не использовать глобально без утверждения.
- **Stable:** документирован, проверен и разрешён для переиспользования.
- **Deprecated:** новым страницам запрещён; указывается замена и план миграции.
- **Removed:** удалён после подтверждения отсутствия потребителей или их миграции.

## Правила изменений
- Не придумывать существующие файлы, пути или библиотеку компонентов.
- Не переписывать имеющийся `AGENTS.md` без объединения его правил.
- Не создавать независимую параллельную систему токенов или вторую UI-библиотеку.
- Не удалять используемые компоненты автоматически; сначала анализ consumers.
- Не полагаться на CSS-only изменение если оно меняет взаимодействия.
- Документированная норма и реальный backend могут расходиться: не подменять фактическую логику. Конфликт сообщить, предложить безопасный план.
