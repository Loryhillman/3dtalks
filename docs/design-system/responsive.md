# Responsive Design System

**Подход:** Desktop First с полноценной функциональной адаптацией обычных веб-страниц. Реальный Three.js viewer вне текущей области.

## Диапазоны
| Диапазон | Ширина viewport | Базовая схема |
|---|---|---|
| Mobile | ≤767 px | 1 колонка; Sidebar как drawer |
| Tablet | 768–1023 px | 1–2 колонки, компактный App Shell |
| Desktop | 1024–1439 px | 2 колонки где позволяют контейнеры |
| Wide Desktop | ≥1440 px | До 3 колонок |

**Контейнер важнее ширины устройства:** при узком содержимом даже на wide не навязывать три карточки; принимать решение по доступной ширине. Изменение breakpoint требует согласования.

## Правила адаптивных паттернов
- **Sidebar:** на телефоне overlay drawer с доступным закрытием, фокусом и backdrop; в tablet может быть 64 px при ограниченном месте; desktop управляется пользователем.
- **Header:** навигация и профиль доступны; длинные breadcrumbs сокращаются семантически, а не обрезают ключевой контекст.
- **Grid:** карточки room/template 16:9 превью, затем метаданные и кнопка; 3/2/1 колонка по вмещаемости.
- **Table:** mobile карточное представление или локальная прокрутка таблицы с сохранением заголовков и данных; не скроллить всю страницу по горизонтали.
- **Form:** метки доступны, поля занимают нужную ширину; action area остаётся достижимой при экранной клавиатуре.
- **Dialog:** desktop max-width по контракту компонента; phone — безопасные поля, overflow content или full-screen при сложной форме.
- **Workspace:** инструменты группируются в панели/drawer/sheets, сохраняется функциональность; не пытаться уменьшить сложную панель до нечитаемых размеров.
- **Touch:** целевые области 44×44 px; функции не доступны только через hover.

## Обязательные проверки
375×812, 430×932, 768×1024, 1280×800, 1920×1080; дополнительно промежуточные ширины и 200% text zoom. Учитывать safe areas, экранную клавиатуру, горизонтальную ориентацию. В рамках WCAG проверять reflow при 320 CSS px где применимо; исключения (например, сложные таблицы) обосновывать.

## Нельзя
- Скрывать «Удалить» или другие значимые операции без альтернативного доступного пути.
- Привязывать кликабельность к hover или к размеру иконки 16 px без достаточной touch target.
- Фиксировать размеры по пикселям без учёта контента и увеличения текста.
- Утверждать поддержку мобильного 3D viewer на основании успешного UI-теста обычных страниц.
