## Возврат к исходникам

При чистом tracked working tree вернуться к завершённому этапу можно командой:

```bash
git switch codex/meeting-room-controls
git rev-parse HEAD
```

Ожидаемый коммит — 2c6660aa. Не применять reset --hard/clean -fd для возврата:
в репозитории есть отдельные пользовательские неотслеживаемые файлы.
Незакоммиченные правки перед переключением сохранить осмысленным коммитом
или отдельной копией; не затирать их.

Для просмотра неизменяемого тега без переключения рабочей ветки:

```bash
git show --stat checkpoint/pre-webrtc-2026-10-20
git show --stat checkpoint/production-2026-10-20
```

Для отдельных исправлений исходной версии создавать новую ветку от нужного
тега. Не передвигать сам тег и не делать force push исходных веток.

## Откат сайта и данных

Git tag сохраняет исходники, но не .env, секреты, БД, загруженные модели,
материалы, сертификаты и состояние внешнего SFU. Для отката сервиса нужны
подходящий образ и совместимая схема/данные; правила — SERVER_DEPLOYMENT.md.

Перед текущей компактной правкой viewer сохранена резервная копия:
 /opt/3dtalks-backups/3dtalks-20261020T122924Z.
На момент закрепления образ сайта — 3dtalks:484546c3; предыдущий — 3dtalks:7fd1de76.
Не удалять эти образы/постоянные тома при подготовке медиа-ветки.
Само создание веток/тегов ничего на сервере не запускает.

До внедрения WebRTC:
1. Новые SQL-миграции должны быть аддитивными и совместимыми с прежним
   runtime. Destructive schema changes в тот же выпуск не включать.
2. Новый медиарежим вводить через явный server-side feature gate.
   Сохранять прежний режим только для явно legacy-комнат; не использовать
   скрытый fallback, обходящий модерацию.
3. Отдельно тестировать rollback приложения после применения миграций.
   Нельзя объявлять откат проверенным только потому, что git switch работает.
4. При переключении режима закрывать текущие media sessions/публикации,
   инвалидировать grants и не оставлять соединения SFU после room end/kick.
5. Образы/настройки SFU версионировать отдельно от app. Перед production
   rollout сохранять .env, БД/файлы и предыдущие app/media images.
6. Восстановление старой БД может потерять новые пользовательские данные;
   не выполнять его автоматически. Сначала определить, достаточно ли
   откатить образ при совместимой схеме.

Полный план: MEETING_ROOM_EVOLUTION.md. Никаких SFU/миграций/изменений сайта
в рамках закрепления этих версий не выполнялось.
