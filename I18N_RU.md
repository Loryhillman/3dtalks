## Модель языка

- Каталоги находятся в `public/i18n/`: `zh-CN.json`, `en-US.json`, `ru-RU.json`; общая библиотека — `i18n.js`.
- `GET /api/config/language` возвращает язык по умолчанию для нового браузера.
- Явный выбор хранится в `preferredLocale`; совместимый ключ `locale` поддерживается для старых страниц. Личный выбор важнее серверного значения.
- `PUT /api/config/language` доступен администратору и меняет язык по умолчанию для новых посетителей. Уже подключённые игроки сохраняют свой выбор.
- Игровой переключатель последовательно выбирает китайский, английский и русский. В админке язык выбирается из списка; выбор администратора также меняет серверное значение по умолчанию.
- Для отсутствующего перевода библиотека пробует английский, затем китайский каталог. Если ключ отсутствует во всех каталогах, возвращается сам ключ — такие случаи нужно исправлять.

## Как добавлять перевод

| Источник | Механизм |
| --- | --- |
| Статический HTML | `data-i18n`, `data-i18n-placeholder`, `data-i18n-title` |
| Динамические надписи | `i18n.t(key)` и `i18n.tp(key, params)`; обработчик смены языка |
| Начальные состояния админки | `data-i18n-initial`; после появления динамических данных обработчик прекращает менять элемент |
| Сообщения API | `errorKey`/`messageKey`, при необходимости `messageParams`; клиент — `i18n.apiMessage(response, fallback)` |
| Стандартные контрольные вопросы | `questionKey`; неизвестный пользовательский текст сохраняется |
| Названия объектов мира и пользовательские данные | Отдельная схема переводов по ID/языку; имена игроков и внутренние идентификаторы не заменяются |

Новый ключ добавляется во все три общих каталога. Параметры записываются как `{{name}}` и совпадают во всех переводах. При обновлении динамического элемента нужно сохранять его состояние и данные. Новую ошибку API снабжать ключом, сохраняя исходный текст для старых клиентов. `apiMessage` при неизвестном ключе возвращает исходный `error`/`message` или переданный резервный текст.

У подписки (`public/js/subscription.js`) и входа в админку (`public/admin_login.html`) собственные словари `zh/en/ru`; они проверяются отдельно и не входят в число 4819.

## Команды проверки

Из корня проекта:

```bash
node scripts/check-i18n.js --strict
node scripts/check-local-i18n.js
node scripts/audit-i18n-project.js --strict --output I18N_AUDIT.json
node scripts/test-i18n.js
```

Команды не запускают сервер, игру или Docker. Тесты используют имитацию браузера и API. Проверяются выбор языка, параметры, начальные состояния, динамические подписи, сообщения API, повтор авторизации без цикла и загрузка перевода микрофона.

Дополнительный поиск китайских литералов:

```bash
node scripts/audit-i18n-literals.js --ui-candidates
node scripts/audit-i18n-literals.js --ui-candidates --file public/js/adminBuildings.js
```

Счётчики разных аудитов нельзя сравнивать напрямую. Поиск литералов не различает полностью интерфейс, резервный текст, комментарии, журналы и внутренние данные. Расширенный аудит также не проверяет все вычисляемые ключи и все серверные маршруты.

`python3 scripts/expand-ru-memory.py` — инструмент изменения каталога, а не проверка: повторно использует уже переведённые русские строки при полном совпадении английского текста. Внешние службы не вызывает. Автоматический черновик с обнаруженными смысловыми ошибками ранее удалён; активный русский каталог редактировался отдельно.

## Что проверить при возобновлении

1. Проверить в браузере вход игрока, админку, редакторы, загрузку моделей, голосовой чат и смену языка. Особенно микрофон, длинные подписи и состояния загрузки/ошибок.
2. Перевести сообщения остальных API и динамические надписи, которые не попадают в текущий аудит.
3. Определить схему перевода системного контента базы: NPC, предметы, типы, порталы и описания; сохранить пользовательские данные и идентификаторы.
4. Проверить смысл перевода и размеры элементов на трёх языках. Завершённость подтвердить по действующим сценариям, а не только по числу ключей.

Для проверки последних изменений пользователь может пересобрать приложение:

```bash
cd ~/projects/3d-virtual-world
docker compose -f docker-compose.local.yml up --build -d
```

Затем обновить страницу через **Ctrl+Shift+R** и выбрать русский язык. Docker daemon должен быть запущен. Инструкции по запуску: [LOCAL_DEVELOPMENT.md](./LOCAL_DEVELOPMENT.md), [RUN_AND_PLAY_RU.md](./RUN_AND_PLAY_RU.md).

## Общий аудит HTML и JavaScript

```bash
node scripts/audit-i18n-project.js --strict --output I18N_AUDIT.json
```

Проверяет статические ключи в HTML, встроенных скриптах и известных функциях перевода JavaScript. Для вызовов `tp` проверяет формат параметров и наличие обязательных полей в объекте параметров.
