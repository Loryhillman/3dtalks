# 3dtalks

Переговорные комнаты в браузере: кабинет пользователя, вход по ссылке,
посадочные места и административный редактор шаблонов помещений.

## Запуск

Нужны Docker Engine и Docker Compose. После клонирования:

```bash
cp .env.example .env
```

Заполните в `.env` четыре обязательных параметра:

| Параметр | Значение |
|---|---|
| `WORLD_URL` | Адрес сайта, например `http://localhost:3002` |
| `DB_PASSWORD` | Пароль PostgreSQL |
| `ADMIN_USERNAME` | Логин первого администратора |
| `ADMIN_PASSWORD` | Пароль первого администратора: от 12 символов, до 72 байт UTF-8 |

```bash
docker compose up -d --build
```

Откройте http://localhost:3002. Админка: http://localhost:3002/admin_login.html.
База, первый администратор, внутренние секреты и шаблон переговорной создаются
автоматически. Дамп и скачивание демонстрационных моделей для новой установки не нужны.
Первый запуск включает сборку образа и может занять несколько минут.

Если запуск не удался, выполните `docker compose logs --tail=100 app`.
Ошибки настроек отмечены `[CONFIG]`: указаны имя параметра и требование к нему,
без вывода паролей. Отсутствующие обязательные значения Compose покажет сразу
в терминале, до создания контейнеров. После исправления `.env` повторите
`docker compose up -d`; простой `restart` не применяет изменения `.env`.

- [Локальная разработка без постоянной пересборки](LOCAL_DEVELOPMENT.md)
- [Запуск на сервере и обновление](SERVER_DEPLOYMENT.md)

Для **существующей установки** сохраните текущий пароль базы и Docker-тома.
Не заменяйте свой `.env` примером. Переход с прежних конфигураций описан в
инструкции локальной разработки.

Код основан на [3d-virtual-world](https://github.com/miduo100/3d-virtual-world).

и [EULA](EULA.md).

## Аватар пользователя

В кабинете откройте **«Мой аватар»**. Можно выбрать стандартное тело с головой
в виде картинки, шара, куба или отдельной GLB-модели; также можно загрузить
персонажа целиком. Предпросмотр использует ту же модель тела и посадку, что и
переговорная. После сохранения внешний вид применяется при следующем входе в
комнату и виден остальным участникам. Настройки привязаны к аккаунту, а не браузеру.

- Изображение: PNG/JPEG/WebP до 8 МБ, обрезается до квадрата по центру.
  На шаре и кубе изображение располагается на плоской передней панели.
- Голова: GLB без скелета, до 20 МБ и 30 000 треугольников.
- Персонаж целиком: GLB до 40 МБ и 100 000 треугольников, с одним совместимым
  человекоподобным скелетом. Нужны таз, голова и цепочки бедро–голень–стопа;
  распознаются названия костей Mixamo и распространённые варианты.
- GLB должен содержать все ресурсы внутри файла. Текстуры — до 4096×4096,
  не более 32 изображений и 16 млн пикселей суммарно. Draco, Meshopt и KTX2 в редакторе аватаров не поддерживаются.
- Лимит на аккаунт: 12 файлов и 100 МБ. Ненужные файлы можно удалить;
  файлы сохранённого аватара и активного сеанса защищены от удаления.

Модели автоматически приводятся к стандартным размерам. Направление модели,
размер и высоту головы можно поправить в предпросмотре. Проверка скелета не
гарантирует идеальную посадку любой модели: итог зависит от её пропорций и
привязки геометрии к костям. Анимации из загруженного GLB пока не воспроизводятся.

Настройки хранятся в PostgreSQL, файлы — в `/app/public/uploads/user-avatars`
в существующем томе загрузок. При переносе на другой сервер нужны база и этот
том; `git push` файлы аватаров не переносит. Миграция базы применяется при запуске.
