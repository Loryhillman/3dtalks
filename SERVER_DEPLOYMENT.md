# Запуск на сервере

Нужны Docker Engine и Docker Compose. Все настройки хранятся в `.env`
в корне проекта: Compose читает его автоматически, без `--env-file`.
Для новой установки на сервере:

```bash
git clone https://github.com/Loryhillman/3dtalks.git
cd 3dtalks
cp .env.example .env
```

Заполните `.env`:

```dotenv
WORLD_URL=http://IP_СЕРВЕРА:3002
DB_PASSWORD='ваш_пароль_базы'
ADMIN_USERNAME=admin
ADMIN_PASSWORD='ваш_пароль_администратора'
BIND_ADDRESS=0.0.0.0
HTTP_PORT=3002
```

Замените адрес и пароли своими. `ADMIN_PASSWORD` — от 12 символов,
до 72 байт UTF-8. Пароли с `$` или `#` заключайте в одинарные кавычки.
`WORLD_NAME` — необязательное название сайта.

```bash
docker compose up -d --build
```

База, первый администратор, секреты и базовый шаблон комнаты создадутся
автоматически. Откройте `http://IP_СЕРВЕРА:3002/`; админка находится на
`/admin_login.html`. В панели хостинга разрешите TCP 3002. База наружу не публикуется.
Для работы микрофона на публичном адресе требуется HTTPS; после настройки
HTTPS укажите соответствующий адрес в `WORLD_URL`.

## Проверка и обновление

```bash
docker compose ps
curl --fail http://127.0.0.1:3002/api/ready
docker compose logs --tail=100 app postgres
```

Ожидаемый ответ проверки: `{"status":"ready"}`. Обновление кода:

```bash
git pull --ff-only
docker compose up -d --build
```

## Существующая установка и данные

На существующем сервере сохраните действующий пароль PostgreSQL и тома:
не заменяйте `.env` примером. При переходе с нашей старой конфигурации перенесите
значения из `.env.server` в `.env`, включая `DB_PASSWORD`, и задайте адрес сайта.
Если `.env` ещё не существует, достаточно переименовать прежний файл:

```bash
mv -n .env.server .env
chmod 600 .env
docker compose config --quiet
docker compose up -d --build
```

`mv -n` не перезаписывает существующий `.env`. Если такой файл уже есть,
проверьте его через `nano .env` и перенесите недостающие значения из прежнего
файла, сохранив действующий пароль базы. После перехода запуск, обновление
и просмотр логов выполняются обычными командами `docker compose` выше.

Новая конфигурация использует прежнее имя проекта `virtual-world-local` и
прежние имена томов. Если старая установка запускалась с другим именем проекта,
сохраните его через `COMPOSE_PROJECT_NAME` в `.env`.
Существующие администраторы не пересоздаются; `.env` не сбрасывает их пароли.

База, модели и изображения хранятся в Docker-томах и не входят в Git.
Новая установка создаёт базовый шаблон; для переноса ваших комнат и мебели
потребуются резервная копия базы и загруженные файлы. Пересборка контейнера
не переносит данные с другого компьютера и не заменяет содержимое томов.

`docker compose down` сохраняет данные. **Не выполняйте `docker compose down -v`**
для рабочей установки. Резервируйте базу, тома с файлами и `.env` отдельно.

Если после переноса файлов появляется `EACCES: permission denied` для папок
загрузок, восстановите владельца файлов в существующих томах:

```bash
docker compose exec --user root app chown -R node:node /app/uploads /app/public/uploads /app/public/models /app/public/generated /app/public/uploaded /app/public/scenes /app/public/gallery_content
```

Команда предназначена для серверной установки без `compose.dev.yaml`.

## Общий экран: проверка перед личной приёмкой

16 октября 2026 проверен и развёрнут код `d7d24db5` из
`codex/room-presentations`. До обновления сохранены дамп PostgreSQL, `.env`,
загруженные файлы/модели/внутренние секреты и предыдущий образ приложения.
На сервере резервные копии находятся в `/opt/3dtalks-backups`; указатель
`latest-presentation-backup` содержит путь к последней копии этого обновления.
Каталог закрыт от обычных пользователей; пароли и токены в Git не сохраняются.

Проверенный Alpine-образ собран локально и перенесён на VPS, чтобы не выполнять
сборку на сервере с 1 ГБ RAM. PostgreSQL и его том не пересоздавались.
Миграции аддитивны, readiness/health приложения и PostgreSQL прошли.
Публикация 8 и исходная комната `123` сохранены; неизменность старого снимка
проверена по резервной копии. В существующий черновик через административный
API добавлен экран, опубликована версия 9 и создана новая комната владельца
«Переговорная с экраном». Следующие новые комнаты используют публикацию 9.

Выполнено:

- Настоящий `node:20-alpine`, Node 20.20.2 и PostgreSQL 18: processor PDF/Sharp,
  HTTP/JWT/Multer/SQL материалов, настоящий WS общего показа, canonical startup
  и миграции дважды. Для тестов использовались отдельные локальные контейнеры,
  временные БД/схемы/файлы; серверная рабочая БД в тестах не использовалась.
- На развёрнутом сайте — два изолированных Chromium-сеанса с настоящими
  API/WS/PostgreSQL: загрузка PDF/изображения, общие страницы, live preview,
  поздний вход после reload, запрет команд участника, выдача без разрешения,
  подтверждаемое удаление активного файла и изоляция второй комнаты.
- Для личной проверки оставлены два образца в новой комнате. Отдельная
  временная комната приёмки архивирована; временный аккаунт удалён.

Повторяемый браузерный сценарий — `scripts/check-room-presentation-live-browser.js`.
Он требует явно заданных `ROOM_LIVE_ACCEPTANCE_URL` и
`ROOM_LIVE_ACCEPTANCE_AUTH_FILE`. Приватный JSON содержит комнату, владельца и
отдельного тестового участника с token/userId/characterId; передавайте только
выделенную комнату приёмки и тестового участника. Сценарий загружает образцы,
создаёт/удаляет комнату участника и оставляет образцы владельцу. Токены не
печатаются. После проверки удаляйте приватный файл и тестовый аккаунт.

Реальные телефоны, Safari/Firefox и пользовательские сложные PDF ещё требуют
ручной проверки. Публичный адрес пока использует HTTP; голосовой микрофон
в обычном браузере требует HTTPS, как указано выше. PDF/изображения и общий
экран проверены на текущем адресе.
