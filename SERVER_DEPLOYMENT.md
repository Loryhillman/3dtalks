# Запуск на сервере

Нужны Docker Engine и Docker Compose. Все настройки хранятся в `.env`
в корне проекта: Compose читает его автоматически, без `--env-file`.
Для новой установки на сервере:

```bash
git clone https://github.com/Loryhillman/3dtalks.git
cd 3dtalks
cp .env.example .env
```

Заполните `.env`:

```dotenv
WORLD_URL=http://IP_СЕРВЕРА:3002
DB_PASSWORD='ваш_пароль_базы'
ADMIN_USERNAME=admin
ADMIN_PASSWORD='ваш_пароль_администратора'
BIND_ADDRESS=0.0.0.0
HTTP_PORT=3002
```

Замените адрес и пароли своими. `ADMIN_PASSWORD` — от 12 символов,
до 72 байт UTF-8. Пароли с `$` или `#` заключайте в одинарные кавычки.
`WORLD_NAME` — необязательное название сайта.

```bash
docker compose up -d --build
```

База, первый администратор, секреты и базовый шаблон комнаты создадутся
автоматически. Откройте `http://IP_СЕРВЕРА:3002/`; админка находится на
`/admin_login.html`. В панели хостинга разрешите TCP 3002. База наружу не публикуется.
Для работы микрофона на публичном адресе требуется HTTPS; после настройки
HTTPS укажите соответствующий адрес в `WORLD_URL`.

## Проверка и обновление

```bash
docker compose ps
curl --fail http://127.0.0.1:3002/api/ready
docker compose logs --tail=100 app postgres
```

Ожидаемый ответ проверки: `{"status":"ready"}`. Обновление кода:

```bash
git pull --ff-only
docker compose up -d --build
```

## Существующая установка и данные

На существующем сервере сохраните действующий пароль PostgreSQL и тома:
не заменяйте `.env` примером. При переходе с нашей старой конфигурации перенесите
значения из `.env.server` в `.env`, включая `DB_PASSWORD`, и задайте адрес сайта.
Если `.env` ещё не существует, достаточно переименовать прежний файл:

```bash
mv -n .env.server .env
chmod 600 .env
docker compose config --quiet
docker compose up -d --build
```

`mv -n` не перезаписывает существующий `.env`. Если такой файл уже есть,
проверьте его через `nano .env` и перенесите недостающие значения из прежнего
файла, сохранив действующий пароль базы. После перехода запуск, обновление
и просмотр логов выполняются обычными командами `docker compose` выше.

Новая конфигурация использует прежнее имя проекта `virtual-world-local` и
прежние имена томов. Если старая установка запускалась с другим именем проекта,
сохраните его через `COMPOSE_PROJECT_NAME` в `.env`.
Существующие администраторы не пересоздаются; `.env` не сбрасывает их пароли.

База, модели и изображения хранятся в Docker-томах и не входят в Git.
Новая установка создаёт базовый шаблон; для переноса ваших комнат и мебели
потребуются резервная копия базы и загруженные файлы. Пересборка контейнера
не переносит данные с другого компьютера и не заменяет содержимое томов.

`docker compose down` сохраняет данные. **Не выполняйте `docker compose down -v`**
для рабочей установки. Резервируйте базу, тома с файлами и `.env` отдельно.

Если после переноса файлов появляется `EACCES: permission denied` для папок
загрузок, восстановите владельца файлов в существующих томах:

```bash
docker compose exec --user root app chown -R node:node /app/uploads /app/public/uploads /app/public/models /app/public/generated /app/public/uploaded /app/public/scenes /app/public/gallery_content
```

Команда предназначена для серверной установки без `compose.dev.yaml`.

## Новый сервер: HTTPS и эксплуатация (20 октября 2026)

На новом пустом VPS (Ubuntu 26.04, x86_64, 1 ГБ RAM, 1,8 ГБ swap) выполнена
чистая установка 3dtalks. Старая серверная база не переносилась: установлен
`meeting-six-v2`, создана новая комната с экраном и образцами PDF/изображения.
Учётные данные проверены входом через браузер и сохраняются в закрытом файле
`/root/3dtalks-access.txt`, вне Git.

Используется дополнительный профиль для небольшого сервера:

```bash
cd /opt/3dtalks
docker compose -f compose.yaml -f compose.production.yaml up -d --build
docker compose -f compose.yaml -f compose.production.yaml ps
```

У приложения предел памяти 512 МиБ (с памятью и swap — 768 МиБ), у PostgreSQL
256/512 МиБ. Ограничены процессы и размер JSON-логов: три файла по 10 МиБ
для каждого сервиса. PostgreSQL использует 64 МиБ shared_buffers, до 60
соединений; приложение по-прежнему работает одним процессом. Это профиль
для небольших встреч, не обещание производительности под любой нагрузкой.
При первом развёртывании перенесены ранее проверенные образы Node 20 Alpine
и PostgreSQL 18; отсутствие изменений runtime относительно проверенного образа
сверено по Git. Контейнеры используют постоянные тома и `unless-stopped`.

Nginx на хосте принимает HTTP/HTTPS, перенаправляет HTTP на HTTPS и передаёт
WebSocket в приложение. `BIND_ADDRESS=127.0.0.1`, `HTTP_PORT=3002`,
`WORLD_URL=https://IP`, `TRUST_PROXY=1`; порт приложения доступен только
локальному reverse proxy, PostgreSQL наружу не опубликован. UFW допускает
входящие SSH, HTTP и HTTPS. Nginx заменяет присланные клиентом forwarded
заголовки проверенным адресом и схемой.

Для IP используется доверенный сертификат Let's Encrypt. Поддержка такого
выпуска через webroot требует Certbot не ниже 5.4; установлен и проверен
Certbot 5.8 в `/opt/certbot` по [инструкции Let's Encrypt](https://letsencrypt.org/2026/03/11/shorter-certs-certbot).
У IP-сертификата срок шесть дней: таймер `3dtalks-cert-renew.timer`
проверяет продление четыре раза в сутки, deploy-hook проверяет и перезагружает
Nginx. Выполнены `renew --dry-run --run-deploy-hooks` и успешный запуск
системного сервиса продления. Порт 80 и ACME webroot должны оставаться доступны.

```bash
systemctl list-timers '3dtalks-*'
systemctl status 3dtalks-cert-renew.service
journalctl -u 3dtalks-cert-renew.service --no-pager -n 30
/opt/certbot/bin/certbot renew --dry-run --run-deploy-hooks
```

### Резервные копии

`scripts/backup-production.sh` создаёт согласованную копию базы и файлов.
Для этого приложение кратко **приостанавливается**: текущие запросы и встречи
могут прерваться, особенно при больших объёмах данных. PostgreSQL продолжает
работать. При завершении/ошибке trap снимает паузу; системный сервис также
имеет аварийный `ExecStopPost` для возобновления контейнера.

Копия включает pg_dump, закрытые материалы, модели/загрузки, внутренние секреты,
`.env`, ревизию кода, идентификатор образа и контрольные суммы. Каталог
`/opt/3dtalks-backups` закрыт правами 0700; незавершённые копии помечены
`.incomplete-*`, успешный путь записывается в `latest`. Сохраняются семь
завершённых копий; тома и чужие каталоги не удаляются.

На этом VPS таймер `3dtalks-backup.timer` запускает копирование в 03:15 UTC
(06:15 Москвы). Проверены создание копии, контрольные суммы, возврат приложения
из паузы и восстановление pg_dump в отдельную временную БД. Исходная рабочая
БД при проверке восстановления не менялась. Копии на том же VPS не защищают
от его потери: переносите завершённые копии в отдельное защищённое хранилище.

```bash
systemctl start 3dtalks-backup.service
systemctl status 3dtalks-backup.service
journalctl -u 3dtalks-backup.service --no-pager -n 30
cat /opt/3dtalks-backups/latest
```

После установки прошёл единый live Chromium/HTTP/WS/PostgreSQL-сценарий двух
аккаунтов: PDF/изображение, общие страницы, live preview, поздний вход, права
владельца, подтверждаемое удаление и изоляция второй комнаты. Дополнительно
проверены доверенный HTTPS и доступ к микрофону с **синтетическим** аудиовходом
Chromium; физические микрофоны и Safari/Firefox требуют пользовательской
проверки. Временный тестовый аккаунт удалён. После пересоздания контейнера
комната, материалы и состояние показа сохранились.
