# Миры, сцены и редакторы: комната со столом и шестью стульями

Дата разбора: 29 сентября 2026 года. Разбор кода без запуска приложения и без изменения карты или базы.

## Термины проекта

| Термин | Что означает в коде | Где хранится |
| --- | --- | --- |
| Игровой мир | Объекты, которые загружаются при входе в игру | `world_objects`; связанные модели и настройки |
| Сцена Three.js | Текущая сцена рендеринга в браузере | Память вкладки; сама по себе не является сохранением |
| Сохранённая AI-сцена | Описание, раскладка и конфигурация генерации | `ai_generated_scenes` |
| Модель в библиотеке | Ресурс, который можно разместить в мире несколько раз | Файл GLB/OBJ либо `geometry_buildings` |
| Объект мира | Размещённый экземпляр модели со своим ID и трансформацией | `world_objects` |
| Федеративный мир | Другая инсталляция проекта на собственном сервере | Отдельный сервер/база, переход через портал |
| Комната | Геометрия помещения и мебель; отдельной сущности комнаты в рассмотренном пути загрузки нет | Набор объектов мира или одна составная модель |

Стол-модель и размещённый стол — разные вещи. Один ресурс стула можно использовать для шести экземпляров с разными позициями и поворотами.

## Как открывается игра

Игровая страница `public/index.html` создаёт `World`. В `public/js/world.js` метод `loadGeneratedBuildings()` получает объекты через `/api/world/objects`, распределяет их по типам и загружает геометрию, модели, код Three.js и медиа. Отдалённые объекты представлены заглушками; реальные модели подгружаются по расстоянию.

`GET /api/world/objects` в `src/routes/world.js` читает всю таблицу `world_objects`. В строках есть `world_id`, но этот маршрут не использует его для выбора карты. Наличие столбца не означает готовый переключатель независимых карт.

Удаление/добавление/изменение объекта — запросы DELETE/POST/PUT к `/api/world/objects`. PUT ожидает отдельные поля `position_x`, `position_y`, `position_z`, `rotation_x` и аналогичные поля масштаба. При обновлении объекта этот маршрут сохраняет базу, но не отправляет событие обновления геометрии в другие вкладки. Для проверки сохранённого результата нужно заново загрузить игру.

## Назначение редакторов

### Редактор мира — `/world_editor.html`

Работает с существующими объектами игрового мира. Поддержаны перемещение одного выбранного объекта с автоматическим сохранением после отпускания манипулятора, изменение свойств, удаление, копирование и размещение загруженных моделей из библиотеки.

Обычная функция `addObject(type)` пока содержит TODO и уведомление о разработке. Она ничего не создаёт. Её нельзя использовать как рабочий способ создания мебели.

`addUploadedModelToScene()` — другой путь: отправляет POST с типом `uploaded_model`, путём ресурса и отдельными координатами. Это подходящая существующая основа для размещения реальных GLB-моделей, но результат POST и отображение после повторного входа всё равно нужно проверить.

Настройки земли читаются и сохраняются через `/api/world/ground-config`. Кнопка применения меняет только предпросмотр; отдельная кнопка сохраняет конфигурацию. Однако игровой `World` пока создаёт землю с фиксированным размером и цветом `0x2d5016`, не загружая эту конфигурацию. Это подтверждённый разрыв между редактором и игрой.

### Объединённый редактор — `/unified_editor.html`

Совмещает генерацию, библиотеку, предпросмотр и редактирование мира. Наличие объекта в предпросмотре не гарантирует запись в базу.

В коде есть несколько самостоятельных путей сохранения:

- `saveScene()` сохраняет заготовку в `ai_generated_scenes` через `/api/ai-scene/save-scene` (префикс берётся из `API_BASE_AI`). Это не само по себе переключение игрового мира.
- `saveGeometrySceneToWorld()` отправляет объекты в API мира, но передаёт вложенные `position`/`rotation`/`scale`, тогда как сервер читает отдельные поля. Сервер также может сохранить тип, который игровой загрузчик не обрабатывает (например `primitive`). Ответ об успешной вставке не доказывает правильное положение и отображение.
- Для `threejs-direct` клиент `saveScene()` отправляет `layout_data: null`, а `/save-scene` в `src/routes/aiSceneGenerator.js` требует непустое `layout_data`. В этой ветке клиент и сервер не согласованы. Кроме того, этот маршрут не сохраняет переданный `threejs_code` в своём INSERT.

Поэтому для первой комнаты лучше использовать простой явный путь размещения моделей или составной геометрии, а не зависеть от AI-генерации и нескольких несовместимых кнопок сохранения.

### Остальные редакторы

`character_editor.html` относится к моделям персонажей и анимациям. `animation_puppeteer.html` — к суставам и движениям. Фабрика анимаций и генератор AI-сцен не нужны для комнаты с обычной мебелью.

## Что уже можно сделать для этой задачи

### Комната внутри текущего мира

1. Подготовить помещение, стол и модель стула. Модели GLB можно загрузить в библиотеку; один стул использовать шесть раз. Альтернатива — геометрия из простых компонентов без скачивания внешних моделей.
2. Разместить помещение, стол и шесть стульев через рабочий путь POST `/api/world/objects` с поддерживаемыми типами и отдельными координатами.
3. Проверить сохранение каждого объекта и его наличие после повторного открытия редактора и игры.
4. При необходимости настроить точку появления рядом с комнатой. Она хранится отдельно в `system_config` под ключом `world_spawn_point`.
5. Открывать игру на том же адресе, когда сервер запущен. Сохранение в базе переживает закрытие вкладки; сервер нужно запускать, чтобы снова войти.

Это сохранит комнату как часть нынешней карты. Автоматическое сидение на стульях, взаимодействие с мебелью и отдельный выбор комнаты из меню этим не обеспечиваются — это самостоятельные функции.

### Независимая комната, которую можно выбирать при входе

Готового надёжного пути «создать карту → сохранить под именем → выбрать карту при входе» в рассмотренной основной цепочке нет. Существующий `world_id` не изолирует загрузку объектов.

Возможны два решения:

- Отдельная инсталляция/база для своего мира: использует существующую модель одного мира на сервер, сохраняет исходную карту отдельно, но требует другого адреса/порта и отдельного обслуживания.
- Доработка одного приложения: каталог сцен, привязка объектов и настроек к сцене, фильтрация API, выбор активной сцены в редакторе/игре и корректная очистка загрузчика при переключении. Это удобнее для кнопки «Открыть комнату», но требует реализации и проверки.

Выбор зависит от того, нужна ли комната частью нынешней карты или независимым сохранением. До выбора и реализации никакие существующие объекты удалять не нужно.

## Минимальный проверяемый результат

Для первой версии:

- Есть комната/помещение, один стол и ровно шесть стульев.
- Стулья размещены вокруг стола и не накладываются друг на друга.
- Координаты, повороты и масштаб сохраняются.
- После закрытия и повторного входа объекты остаются на месте.
- Перемещение, добавление и удаление дают понятный результат сохранения; уведомление об успехе появляется после подтверждения API.
- Нет запросов 404 для моделей этой комнаты.
- Если выбрано независимое сохранение, открытие комнаты не подмешивает объекты исходной карты.

## Какие исправления нужны

1. Согласовать форматы и поддерживаемые типы объектов между редактором, API и игровым загрузчиком.
2. Устранить ложные сообщения успешного сохранения до получения результата запроса.
3. Подключить сохранённые настройки земли к игровому миру, если они нужны для комнаты.
4. Реализовать либо надёжное размещение/сохранение комнаты в текущем мире, либо независимые сцены согласно выбранному варианту.
5. Проверить полный сценарий: создать → сохранить → закрыть → открыть → изменить → открыть снова. Статический разбор этого не заменяет.
