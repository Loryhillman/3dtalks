# Локальный запуск и возможности игры

Инструкция для WSL2 (Ubuntu) с установленным **Docker Engine внутри WSL**, без Docker Desktop. Все команды выполняются в терминале WSL из каталога проекта `/root/projects/3d-virtual-world`. Это локальная конфигурация для разработки: веб-сервер доступен только на `localhost:3002`, порт PostgreSQL наружу не опубликован.

## 1. Запустить Docker Engine

После перезапуска WSL проверьте, работает ли демон:

```bash
docker info
```

Если вывод содержит `Cannot connect to the Docker daemon at unix:///var/run/docker.sock`, запустите установленный в WSL сервис и повторите проверку:

```bash
ulimit -Sn 1024
service docker start
docker info
```

Команды выше рассчитаны на терминал `root`, который используется в этом проекте. Если Docker Engine запущен через `systemd`, подходит `systemctl start docker`. Установка Docker Desktop не требуется.

## 2. Поднять проект

```bash
cd /root/projects/3d-virtual-world
docker compose -f docker-compose.local.yml up --build -d
docker compose -f docker-compose.local.yml ps
curl -i http://localhost:3002/api/ready
```

Дождитесь, пока сервисы `postgres` и `app` получат статус `healthy`. Ожидаемый ответ последней команды: `HTTP/1.1 200 OK` и `{"status":"ready"}`. При первом запуске импорт базы из `db_export.sql` может занять время. `ready` проверяет подключение приложения к базе и наличие основных таблиц; это более полезная проверка запуска, чем `/api/health`.

Откройте в браузере:

| Адрес | Назначение |
| --- | --- |
| <http://localhost:3002/> | Игровой мир, регистрация и вход игрока |
| <http://localhost:3002/admin_login.html> | Вход администратора |
| <http://localhost:3002/admin.html> | Панель администратора после входа |

Согласно README проекта, начальный администратор — `admin` / `admin123456`. Смените этот пароль после первого входа. **Администратор и игрок — разные типы учётных записей.** Для игры создайте отдельного игрока через регистрацию на главной странице. Вход в админку сам по себе не создаёт игрового персонажа.

При первом запуске Compose создаёт отдельный том PostgreSQL 18, импортирует в него `db_export.sql` и сохраняет данные. Ключи приложения и загруженные файлы также хранятся в отдельных томах. Повторная сборка образа не импортирует дамп заново и не сбрасывает прогресс.

## 3. Повседневные команды

```bash
# Проверить состояние
docker compose -f docker-compose.local.yml ps

# Смотреть журнал приложения при ошибке
docker compose -f docker-compose.local.yml logs --tail=100 app

# Смотреть журнал базы
docker compose -f docker-compose.local.yml logs --tail=100 postgres

# Пересобрать приложение после изменения исходников
docker compose -f docker-compose.local.yml up --build -d

# Остановить контейнеры с сохранением данных
docker compose -f docker-compose.local.yml down

# Открыть локальную базу из контейнера
docker compose -f docker-compose.local.yml exec postgres psql -U postgres -d virtual_world
```

Не добавляйте `-v` к `down`, если нужны база, учётные записи и загруженные материалы. `npm run dev` запускает только Vite и не заменяет полный сервер Express с PostgreSQL; для первого знакомства используйте Compose.

## 4. Если что-то не работает

| Симптом | Что проверить или сделать |
| --- | --- |
| `Cannot connect to the Docker daemon` | Запустить сервис Docker в WSL, как в разделе 1, и проверить `docker info`. |
| `app` постоянно `Restarting` | Посмотреть `docker compose -f docker-compose.local.yml logs --tail=100 app`; по последней ошибке определить причину. |
| `EACCES` для `/app/.local-state/secrets.json` после обновления старого образа | Один раз исправить владельца тома командой ниже, затем снова поднять приложение. |
| `curl` возвращает `Connection refused` | Убедиться, что `app` имеет статус `healthy`; если нет, проверить его журнал. Также проверить, что порт `3002` свободен. |
| `Character not found` при входе игрока | Частая причина — старый токен и ID персонажа в браузере после перехода на новую базу. Пересобрать приложение, затем выйти и зарегистрировать нового игрока. Если страница продолжает использовать старую сессию, очистить данные сайта `localhost:3002` в браузере и войти заново. Это удалит только локальное состояние браузера, не базу. |
| Админка открывается, а игрок не входит | Учётная запись администратора не является учётной записью игрока. Зарегистрировать игрока на главной странице. |

Исправление прав старого тома при ошибке `EACCES`:

```bash
docker compose -f docker-compose.local.yml run --rm --no-deps --user root --entrypoint sh app -c 'chown -R node:node /app/.local-state'
docker compose -f docker-compose.local.yml up --build -d
```

## 5. Что можно делать в игре

Оценка ниже основана на исходном коде клиента и сервера. Наличие конкретного монстра, магазина, NPC или портала в мире зависит от данных базы и настроек администратора; все игровые сценарии вручную в браузере не проверялись.

### Гость

- Войти в 3D-мир без регистрации, осмотреть сцену и перемещаться.
- Видеть других участников при подключённом WebSocket и пользоваться чатом поблизости.
- Получить предложение зарегистрироваться или войти для сохранения персонажа.
- Гостю недоступны некоторые действия с постоянным персонажем: профиль, инвентарь и телепортация через порталы. Атака ограничена отсутствием обычных характеристик персонажа.

### Зарегистрированный игрок

- Создать персонажа, перемещаться по миру, прыгать, ускоряться и менять вид камеры; состояние игрока синхронизируется с другими участниками через WebSocket.
- Открывать профиль, менять доступные параметры персонажа, просматривать инвентарь и использовать предметы.
- Общаться текстом с игроками поблизости; голосовые сообщения через микрофон тоже предусмотрены интерфейсом и требуют разрешения браузера.
- Выбирать монстров, атаковать их и подбирать выпавшие предметы, если монстры размещены в мире.
- Использовать локальные порталы и телепортацию по координатам. Переход в **другой серверный мир** требует второго узла и настройки доверия между мирами.
- Открывать каталог магазина при наличии магазина поблизости. Покупку пока не стоит считать рабочей: обработчик клика в игровом интерфейсе выводит сообщение о покупке, но не вызывает серверный метод покупки.
- Видеть размещённые медиаобъекты и галереи, если они добавлены администратором.

### Администратор мира

- Управлять пользователями, ролями, порталами, настройками мира и подключением других миров.
- Создавать и размещать сцены, объекты, модели, персонажей, анимации и другой контент через панель и редакторы.
- Настраивать монстров, NPC, магазины, инвентарь и другие элементы игрового мира через соответствующие модули. Состав реально работающих операций зависит от конкретного модуля.

### Управление с клавиатуры

| Клавиша | Действие по текущему коду клиента |
| --- | --- |
| `W` `A` `S` `D` | Движение |
| `Space` | Прыжок |
| `Shift` | Ускорение |
| `C` | Переключить камеру |
| `M` | Показать или скрыть миникарту |
| `Enter` | Открыть поле чата; повторное нажатие отправляет сообщение |
| `I` | Взаимодействовать с магазином поблизости |
| `P` | Установить точку возрождения |
| `F` | Включить звук ближайшего видеообъекта |
| `Esc` | Снять боевую фиксацию цели; также используется в интерфейсе выхода |

Подсказка на игровой странице называет `F` клавишей взаимодействия, но текущий обработчик назначает взаимодействие с магазином на `I`, а `F` — на звук видео. Это расхождение в интерфейсе.

### Что пока выглядит незавершённым

- Покупка в игровом окне магазина показывает сообщение без вызова API покупки. Серверный маршрут покупки существует, но окно к нему не подключено.
- Метод распознавания голосовой команды для активации навыка (`triggerByVoice`) пока всегда возвращает `false`. Это отдельная функция от голосовых сообщений игрокам.
- Набор возможностей сильно зависит от наполнения базы. Локальный импорт даёт стартовые данные, но наличие каждого объекта и путь к нему стоит проверять в запущенном мире.
